# Практика 4 — SPI-дисплей SSD1306

**Студентка:** Старинская Светлана Романовна.  
**Дисциплина:** Программирование микроконтроллеров.  
**Результат:** шахматная доска с клетками 8×8 пикселей на дисплее SSD1306 128×64.

Работа адаптирована по предоставленному примеру `Antonov_lab4.zip` и учебному шаблону `kn02262/stm32_pm2026`. Происхождение основы сохранено; эта адаптация не заявляет независимое создание всего шаблона и исходного решения.

## Соответствие заданию

Условие взято из карточки «Практика 4 — SPI-дисплей SSD1306» в Obsidian и приложенной презентации «Практика 4. Дисплей SPI». Отдельный номер варианта в этих материалах не указан.

Реализованы функции `SPI1_Init`, `SPI1_Write`, `SPI1_Read`, передача команд и данных SSD1306 и вывод шахматной доски. Подключение — четырёхпроводный SPI. Обратная линия MISO дисплею не требуется; `SPI1_Read` присутствует как учебная функция и при выводе изображения не вызывается.

Страница сдачи: https://lms.kantiana.ru/mod/assign/view.php?id=385089.

## Что изменено относительно примера

- Указаны имя студентки и название работы; цель сборки переименована в `starinskaya_lab4`.
- В `SPI1_Write` добавлены ожидание RXNE и чтение DR. При полном дуплексе приём происходит и во время записи; оставленные непрочитанными байты могли вызвать переполнение OVR.
- В `SPI1_Read` добавлены ожидания TXE перед обменом и окончания BSY перед возвратом.
- В инициализации SSD1306 явно заданы 64 строки, смещение, конфигурация COM и обычный вывод содержимого RAM. Дисплей включается после заполнения кадра.
- В CMake кросс-компилятор выбирается до включения языка C через `project()`. Переменная `ARM_TOOLCHAIN_PATH` принимает путь к каталогу `bin` без обязательного завершающего разделителя.
- В рабочем пространстве оставлены дисплей и подпись работы. Посторонний пример с DS1621, виртуальный терминал и ссылки на проект другого компьютера удалены.
- В `.pzw` помещены новая прошивка и полный комплект исходников. Схема подключения, обязательная шахматная доска и корректная маска GPIO исходного примера сохранены.

## Подключение

Плата: **Blue Pill, STM32F103C8T6**. В проекте PicSimLab используются следующие соединения:

| SSD1306 | STM32 | Номер вывода корпуса в PicSimLab |
|---|---|---:|
| CLK | PA5 / SPI1 SCK | 15 |
| DIN | PA7 / SPI1 MOSI | 17 |
| /RES | PA2 | 12 |
| DC | PA1 | 11 |
| /CS | PA4 | 14 |

Последний параметр компонента `LCD ssd1306` равен `0`, что соответствует SPI в сохранённой схеме. MISO не подключается. При сборке физической схемы необходимо также обеспечить совместимое питание и общую землю.

PA1, PA2 и PA4 — обычные выходы push-pull. PA5 и PA7 — выходы альтернативной функции push-pull. SPI1 работает ведущим, передаёт старший бит первым, использует режим 3 (`CPOL=1`, `CPHA=1`) и частоту `PCLK2/256`. CS управляется программно; при простое он равен 1.

## Как работает программа

1. `SPI1_Init` включает тактирование GPIOA, AFIO и SPI1 и настраивает выводы.
2. `oled_setup` выполняет аппаратный сброс SSD1306 и отправляет команды настройки. Пока изображение не готово, дисплей выключен.
3. `draw_chessboard` задаёт диапазон столбцов 0–127 и страниц 0–7 и передаёт 1024 байта изображения.
4. Команда `0xAF` включает экран. Изображение остаётся статичным, основная программа переходит в бесконечный цикл.

Один байт RAM дисплея содержит восемь вертикальных пикселей. Поэтому для клетки высотой 8 пикселей достаточно передать `0xFF` или `0x00`. Выражение `(page + (col >> 3)) & 1U` меняет цвет через каждые восемь столбцов и при переходе к следующей странице. На экране получается 16 клеток по горизонтали и 8 по вертикали.

Память кадра: `128 × 64 / 8 = 1024` байта. Отдельный буфер изображения в RAM микроконтроллера не создаётся: байты вычисляются и сразу передаются дисплею.

DC равен 0 для команд и 1 для данных изображения. CS удерживается в 0 до окончания передачи байта. TXE означает освобождение передающего буфера, RXNE — наличие принятого байта, BSY — незавершённый обмен на шине.

`sys_delay` — программная задержка в итерациях, а не таймер с гарантированной длительностью в миллисекундах. Скорость симуляции PicSimLab и частота системного тактирования, выбранная кодом STM32, не следует считать одним и тем же параметром.

## Открытие готового результата

1. В PicSimLab 0.9.3 выберите **File → Load Workspace** и откройте `Starinskaya_lab4.pzw`.
2. Проверьте, что выбрана Blue Pill с `stm32f103c8t6`, симуляция запущена, а окно **Spare parts** открыто.
3. Дождитесь выполнения начальных задержек. На SSD1306 должна появиться шахматная доска, заполняющая весь экран.

Прошивка уже находится внутри `.pzw`, поэтому отдельно загружать `.bin` для обычного просмотра не нужно. Если изображение не появилось, сначала выполните сброс платы и проверьте, что симуляция не остановлена.

В `.pzw` исходники размещены по пути `picsimlab_workspace/code/stm32_pm2026/`. Контейнер имеет формат ZIP: чтобы извлечь исходники отдельно, откройте копию `.pzw` архиватором. Внешние абсолютные пути к компьютеру студента для загрузки прошивки не нужны.

Сохранение проекта через другую версию PicSimLab может перепаковать контейнер. Сохраняйте исходный выданный файл или отдельный комплект исходников.

## Сборка из исходников

Нужны ARM GCC с `arm-none-eabi-gcc` и `arm-none-eabi-objcopy`, CMake не ниже 3.18 и генератор сборки, например Ninja или GNU Make. Из каталога `stm32_pm2026`:

```sh
cmake -S . -B build
cmake --build build
cmake --build build --target hex
```

В Windows с установленным Ninja можно явно выбрать генератор:

```powershell
cmake -S . -B build -G Ninja
cmake --build build
```

Если ARM GCC отсутствует в PATH, перед конфигурацией задайте `ARM_TOOLCHAIN_PATH` равным пути к каталогу `bin` установленного ARM GCC. Результаты сборки: `build/starinskaya_lab4.elf`, `.bin` и, после цели `hex`, `.hex`.

Для проверки своей пересобранной программы загрузите новый `.bin` через **File → Load Hex** в PicSimLab и сохраните отдельное рабочее пространство. Поставляемый `.pzw` сам по себе не меняется при последующей сборке исходников.

- Из реально выполненного кода получены 1024 байта кадра. Проверены все 8192 пикселя: клетки имеют размер 8×8, чередование корректно, включение дисплея следует после передачи изображения.

`chessboard.png` в полном комплекте — визуализация байтов, полученных при проверке ARM-кода. Это не скриншот PicSimLab.
